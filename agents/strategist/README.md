# Агент-стратег (Strategist)

## Роль в системе

Формирует контент-план кампании. Преобразует отобранные тренды и параметры персонажа в упорядоченную очередь концептов контента, готовых к передаче агенту-креатору.

## Зона ответственности

- Формирование концептов контента на основании отчёта по трендам и параметров персонажа
- Определение формата и целевой платформы для каждого концепта
- Приоритизация концептов в рамках контент-плана
- Применение механик, направленных на повышение виральности публикаций
- Учёт рекомендаций системы A/B-тестирования при формировании последующих планов
- Формирование плана на базовых сценариях персонажа при отсутствии применимых трендов

## Обоснование выбора модели

Подсистема решает задачу планирования с учётом множества разнородных ограничений: параметров персонажа, ограничений брифа, приоритетов трендов и результатов предшествующих кампаний. Применяется модель Claude Sonnet 5, обеспечивающая требуемое качество рассуждений при приемлемых издержках.

## Защита данных

Механики повышения виральности, весовые коэффициенты приоритизации концептов и шаблоны сценариев персонажа относятся к коммерческой тайне. Модуль обращается к ним по ссылкам (`playbook_ref`, `scenario_templates_ref`) без раскрытия содержимого. Системный промпт агента размещён в закрытой ветке разработки.

## Входной контракт

Модуль принимает отчёт по трендам от агента-аналитика трендов и контекст кампании от ядра персонажа:

```json
{
  "context": {
    "profile": {
      "character_id": "nick_v1",
      "profile_version": "3.2",
      "identity_ref": "vault://character-dna/nick_v1",
      "behavioral_state": {
        "tone": "ироничный, дружелюбный",
        "engagement_trend": "growing"
      }
    },
    "brief": {
      "campaign_id": "camp_2026_demo",
      "character_id": "nick_v1",
      "goal": "Повысить вовлечённость аудитории на короткий период",
      "constraints": ["без упоминания конкурентов", "без резких высказываний"]
    }
  },
  "trend_report": {
    "accepted": [
      {
        "trend_id": "trd_a1",
        "title": "Формат коротких вертикальных обзоров",
        "relevance_score": 0.87
      }
    ]
  },
  "ab_recommendations": []
}
```

Структуры `CampaignContext` и `TrendReport` соответствуют выходным контрактам ядра персонажа и агента-аналитика трендов. Преобразование данных на стыке модулей не требуется.

## Выходной контракт

Модуль возвращает контент-план с упорядоченной очередью концептов:

```json
{
  "campaign_id": "camp_2026_demo",
  "character_id": "nick_v1",
  "created_at": "2026-09-01T18:30:00Z",
  "concepts": [
    {
      "concept_id": "cpt_001",
      "title": "Короткий вертикальный обзор новинки",
      "format": "short_video",
      "target_platform": "telegram",
      "priority": 1,
      "source_trend_id": "trd_a1",
      "key_message": "Демонстрация продукта в характерной для персонажа подаче",
      "virality_mechanics": ["hook_first_3s", "open_question_ending"]
    }
  ],
  "fallback_used": false
}
```

Поле `fallback_used` принимает значение `true`, если контент-план сформирован на базовых сценариях персонажа при пустом списке принятых трендов.

## Форматы контента

| Код | Значение |
|---|---|
| `short_video` | Короткое вертикальное видео |
| `image_post` | Публикация с изображением |
| `carousel` | Серия изображений |
| `text_post` | Текстовая публикация |
| `story` | Материал формата «истории» |

## Производственный цикл

Контент-план формируется на недельный производственный цикл. Целевой показатель проекта — не менее 70 концептов в неделю — относится к производству комплекса в целом и не является ограничением числа концептов в отдельном плане.

## Калибруемые параметры

Предельное число концептов в контент-плане (`max_concepts_per_plan`) определяется по результатам эксплуатации на Этапе 2 на основании фактической пропускной способности контура утверждения и числа кампаний, обрабатываемых в одном производственном цикле.

## Модель данных и конфигурация агента

- [`models.py`](models.py) — структуры данных: концепт контента, контент-план, рекомендация A/B-тестирования
- [`agent.py`](agent.py) — конфигурация агента и контракт методов (без реализации логики)

## Взаимодействие с другими подсистемами

1. Ядро персонажа передаёт объект `CampaignContext`
2. Агент-аналитик трендов передаёт объект `TrendReport`
3. Система A/B-тестирования передаёт рекомендации по результатам предшествующих кампаний
4. Агент формирует объект `ContentPlan` и передаёт его агенту-креатору

## Обработка ошибок

- При пустом списке принятых трендов контент-план формируется на базовых сценариях персонажа, поле `fallback_used` устанавливается в значение `true`
- При недоступности хранилища шаблонов сценариев обработка прерывается с кодом `TEMPLATES_UNAVAILABLE`, кампания переводится в состояние `failed` с фиксацией причины в журнале выполнения
- При конфликте ограничений брифа и приоритетов трендов приоритет отдаётся ограничениям брифа, конфликтующие концепты исключаются из плана
