# Агент-аналитик трендов (Trend Analyst)

## Роль в системе

Обеспечивает опору контент-плана на актуальную повестку. Выполняет мониторинг внешних источников, отбор трендов, применимых к конкретному персонажу, и передачу отфильтрованного списка агенту-стратегу.

## Зона ответственности

- Сбор сигналов о трендах из внешних источников (социальные сети, тематические каналы)
- Оценка каждого тренда на применимость к персонажу: тематическое соответствие, соответствие образу, риск репутационных последствий
- Отсев трендов, не прошедших фильтрацию, с указанием причины отказа
- Ранжирование прошедших трендов по приоритету для агента-стратега

## Обоснование выбора модели

Подсистема выполняет обработку потоковых данных с последующей классификацией без задач генеративного характера. Применяется модель Claude Haiku 4.5, обеспечивающая требуемую производительность при меньших издержках на обработку единицы сигнала.

## Защита данных

Критерии отбора трендов и весовые коэффициенты ранжирования настраиваются под каждого персонажа и относятся к коммерческой тайне. Модуль обращается к ним по ссылке (`scoring_profile_ref`), не раскрывая содержимое. Системный промпт агента находится в закрытой ветке разработки.

## Входной контракт

Модуль принимает контекст кампании, сформированный ядром персонажа:

```json
{
  "profile": {
    "character_id": "nick_v1",
    "profile_version": "3.2",
    "identity_ref": "vault://character-dna/nick_v1",
    "behavioral_state": {
      "tone": "ироничный, дружелюбный",
      "recent_topics": ["..."],
      "engagement_trend": "growing"
    }
  },
  "brief": {
    "campaign_id": "camp_2026_demo",
    "character_id": "nick_v1",
    "goal": "Повысить вовлечённость аудитории на короткий период",
    "constraints": ["без упоминания конкурентов", "без резких высказываний"]
  }
}
```

Структура соответствует объекту `CampaignContext`, формируемому ядром персонажа. Преобразование данных на стыке модулей не требуется.

## Выходной контракт

Модуль возвращает отранжированный отчёт по трендам:

```json
{
  "campaign_id": "camp_2026_demo",
  "character_id": "nick_v1",
  "collected_at": "2026-09-01T18:00:00Z",
  "accepted": [
    {
      "trend_id": "trd_a1",
      "title": "Формат коротких вертикальных обзоров",
      "source": "telegram",
      "relevance_score": 0.87,
      "rationale": "Соответствует тематике персонажа и текущему тону коммуникации"
    }
  ],
  "rejected": [
    {
      "trend_id": "trd_b7",
      "title": "Обсуждение конкурирующего бренда",
      "rejection_reason": "constraint_violation"
    }
  ]
}
```

Отклонённые тренды сохраняются в отчёте с указанием причины отклонения. Это обеспечивает трассируемость решений об отборе и возможность последующего пересмотра критериев.

## Причины отклонения

| Код | Значение |
|---|---|
| `off_topic` | Тренд не соответствует тематике персонажа |
| `tone_mismatch` | Тренд не соответствует коммуникативному стилю персонажа |
| `constraint_violation` | Тренд нарушает ограничения, заданные в брифе |
| `reputational_risk` | Тренд несёт риск репутационных последствий |
| `expired` | Тренд утратил актуальность на момент обработки |

## Калибруемые параметры

Пороговое значение оценки применимости тренда (`min_relevance_score`) определяется по результатам калибровки на реальных данных на Этапе 2. Шкала оценки применимости устанавливается совместно с выбором метода оценки.

## Модель данных и конфигурация агента

- [`models.py`](models.py) — структуры данных: сигнал тренда, оценённый тренд, отчёт по трендам
- [`agent.py`](agent.py) — конфигурация агента и контракт методов (без реализации логики)

## Взаимодействие с другими подсистемами

1. Ядро персонажа передаёт объект `CampaignContext`
2. Агент собирает сигналы о трендах из подключённых источников
3. Каждый сигнал оценивается на применимость к персонажу с учётом ограничений брифа
4. Сформированный отчёт `TrendReport` передаётся агенту-стратегу для построения контент-плана

## Обработка ошибок

- Если внешний источник недоступен — агент продолжает работу по остальным источникам, недоступный источник фиксируется в поле `degraded_sources` отчёта; полная остановка кампании из-за одного источника не допускается
- Если ни один тренд не прошёл фильтрацию — отчёт возвращается с пустым списком `accepted`, агент-стратег в этом случае строит контент-план на базовых сценариях персонажа без опоры на текущую повестку

## Статус
