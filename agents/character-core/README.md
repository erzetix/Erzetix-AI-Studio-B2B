# Ядро персонажа (Character Core)

## Роль в системе

Единый источник достоверных сведений (single source of truth) об идентичности виртуального персонажа: визуальная айдентика, голосовые характеристики, черты поведения, коммуникативный стиль. Все остальные агенты получают контекст о персонаже только через этот модуль.

Персонаж создаётся командой под бренд конкретной компании и закрепляется за ней (`client_id`). Параметры персонажа согласуются с компанией вне комплекса.

## Зона ответственности

- Приём брифа, сформированного командой в рабочем месте команды
- Обогащение брифа актуальным состоянием персонажа (профиль + поведенческий контекст)
- Формирование контекста кампании, который оркестратор передаёт последующим подсистемам
- Приём результатов кампаний от агента-аналитика метрик и обновление поведенческой логики персонажа

## Обоснование выбора модели

Подсистема формирует контекст кампании с учётом параметров идентичности и поведенческого состояния персонажа. Применяется модель Claude Sonnet 5, обеспечивающая требуемое качество при приемлемых издержках.

## Защита данных

Параметры идентичности персонажа (Character DNA, Facial DNA, Body DNA, Style DNA, Prompt DNA) относятся к коммерческой тайне и размещаются в отдельном защищённом хранилище. Модуль обращается к ним по ссылке (`identity_ref`) без раскрытия содержимого. Системный промпт агента и логика валидации идентичности размещены в закрытой ветке разработки. В открытом репозитории представлен контракт модуля.

## Права на персонажа

Принадлежность прав на персонажа определяется договором с компанией и фиксируется в профиле персонажа (`ownership`).

| Код | Значение |
|---|---|
| `studio` | Права на персонажа принадлежат команде |
| `client` | Права на персонажа принадлежат компании |
| `shared` | Права на персонажа распределены между компанией и командой по условиям договора |

Условия договора относятся к защищаемым сведениям. Модуль обращается к ним по ссылке (`rights_agreement_ref`) без раскрытия содержимого.

## Входной контракт

Модуль принимает бриф в следующем формате:

```json
{
  "campaign_id": "camp_2026_demo",
  "character_id": "nick_v1",
  "goal": "Повысить вовлечённость аудитории на короткий период",
  "constraints": ["без упоминания конкурентов", "без резких высказываний"],
  "deadline": "2026-09-15",
  "requested_by": "specialist_01"
}
```

## Выходной контракт

Модуль возвращает обогащённый контекст кампании:

```json
{
  "profile": {
    "character_id": "nick_v1",
    "client_id": "erzetix_media",
    "ownership": "studio",
    "display_name": "Ник",
    "identity_ref": "vault://character-dna/nick_v1",
    "voice_profile_ref": "vault://voice-profile/nick_v1",
    "behavioral_state": {
      "tone": "ироничный, дружелюбный",
      "recent_topics": ["..."],
      "engagement_trend": "growing"
    },
    "profile_version": "3.2",
    "updated_at": "2026-09-01T17:00:00Z"
  },
  "brief": { "...": "исходный бриф без изменений" }
}
```

Поля `identity_ref` и `voice_profile_ref` содержат ссылки на защищённое хранилище, а не сами данные. Запрос содержимого выполняется последующими подсистемами через отдельный сервис доступа с проверкой прав.

## Модель данных и конфигурация агента

- [`models.py`](models.py) — структуры данных (Pydantic): профиль персонажа, бриф, контекст кампании
- [`agent.py`](agent.py) — конфигурация агента и контракт методов (без реализации логики)

## Взаимодействие с другими подсистемами

1. Рабочее место команды передаёт бриф оркестратору, оркестратор — ядру персонажа
2. Ядро запрашивает у защищённого хранилища ссылки на актуальную версию профиля персонажа
3. Ядро формирует объект `CampaignContext` и возвращает его оркестратору; оркестратор сохраняет контекст на протяжении всей обработки кампании и передаёт его каждой последующей подсистеме без изменений
4. После завершения цикла публикации агент-аналитик метрик передаёт результаты обратно в ядро для обновления `behavioral_state`

## Обработка ошибок

- Если профиль персонажа не найден или версия устарела — запрос отклоняется с кодом `PROFILE_NOT_FOUND` / `PROFILE_STALE`, дальнейшая обработка не запускается
- Если хранилище идентичности недоступно — модуль повторяет запрос с экспоненциальной задержкой (retry с backoff), при исчерпании попыток кампания переводится в состояние `failed` с фиксацией причины в журнале выполнения
