# Агент-хранитель бренда (Brand Guardian)

## Роль в системе

Выполняет автоматическую проверку сформированных материалов перед передачей в контур Human-in-the-Loop. Является последней автоматической проверкой перед участием человека.

## Зона ответственности

- Проверка визуальной консистентности персонажа между материалами
- Проверка соответствия материалов требованиям бренда клиента
- Проверка соответствия материалов внутренним правилам допустимого контента
- Проверка соблюдения ограничений, заданных в брифе кампании
- Формирование замечаний для агента-креатора и агента-визуализатора при выявлении несоответствий
- Эскалация материалов контуру Human-in-the-Loop при исчерпании числа циклов доработки

## Обоснование выбора модели

Основной цикл проверки выполняется моделью Claude Sonnet 5. Для случаев, требующих оценки неоднозначного контекста — потенциальный репутационный риск, неочевидное нарушение требований бренда, конфликт между требованиями клиента и внутренними правилами — предусмотрена эскалация на модель Claude Opus 4.8. Эскалация выполняется по решению подсистемы, а не для каждого материала, что ограничивает издержки применения модели более высокого уровня возможностей.

## Защита данных

Правила допустимого контента, требования брендов клиентов и эталонные параметры визуальной идентичности персонажа относятся к коммерческой тайне. Модуль обращается к ним по ссылкам (`brand_rules_ref`, `identity_ref`) без раскрытия содержимого. Системный промпт агента размещён в закрытой ветке разработки.

## Категории проверок

| Категория | Предмет проверки |
|---|---|
| `visual_consistency` | Соответствие внешности персонажа эталонным параметрам |
| `brand_compliance` | Соответствие требованиям бренда клиента |
| `content_policy` | Соответствие внутренним правилам допустимого контента |
| `brief_constraints` | Соблюдение ограничений, заданных в брифе |
| `reputational_risk` | Наличие риска репутационных последствий |

Проверка категории `visual_consistency` выполняется независимо от самопроверки, выполняемой агентом-визуализатором при генерации. Результат самопроверки подсистемы-исполнителя не является основанием для пропуска проверки.

## Входной контракт

Модуль принимает набор медиаматериалов от агента-визуализатора, набор текстовых материалов от агента-креатора и контекст кампании:

```json
{
  "context": {
    "profile": {
      "character_id": "nick_v1",
      "identity_ref": "vault://character-dna/nick_v1"
    },
    "brief": {
      "campaign_id": "camp_2026_demo",
      "constraints": ["без упоминания конкурентов", "без резких высказываний"]
    }
  },
  "draft_bundle": {
    "revision": 1,
    "drafts": []
  },
  "asset_bundle": {
    "revision": 1,
    "assets": []
  }
}
```

Структуры `DraftBundle` и `AssetBundle` соответствуют выходным контрактам агента-креатора и агента-визуализатора. Преобразование данных на стыке модулей не требуется.

## Выходной контракт

Модуль возвращает заключение по каждому материалу:

```json
{
  "campaign_id": "camp_2026_demo",
  "character_id": "nick_v1",
  "reviewed_at": "2026-09-01T20:00:00Z",
  "revision": 1,
  "verdicts": [
    {
      "draft_id": "drf_001",
      "verdict": "approved",
      "checks_passed": [
        "visual_consistency",
        "brand_compliance",
        "content_policy",
        "brief_constraints",
        "reputational_risk"
      ],
      "escalated_to_senior_model": false
    },
    {
      "draft_id": "drf_002",
      "verdict": "revision_required",
      "failed_checks": ["brief_constraints"],
      "revision_notes": [
        {
          "note_id": "nte_001",
          "draft_id": "drf_002",
          "target_agent": "creator",
          "category": "brief_constraints",
          "issue": "Материал содержит упоминание, нарушающее ограничение брифа",
          "required_action": "Исключить упоминание и переформулировать сообщение"
        }
      ]
    }
  ],
  "escalated_to_human": []
}
```

Поле `target_agent` определяет, какой подсистеме направляется замечание: агенту-креатору при несоответствии текстовой составляющей, агенту-визуализатору при несоответствии визуальной.

## Виды заключений

| Код | Значение |
|---|---|
| `approved` | Материал допущен к передаче в контур Human-in-the-Loop |
| `revision_required` | Материал направлен на доработку с замечаниями |
| `rejected` | Материал отклонён без возможности доработки |
| `escalated` | Материал передан человеку без автоматического заключения |

## Калибруемые параметры

Условия эскалации на модель более высокого уровня возможностей определяются по результатам эксплуатации на Этапе 2. Правила формируются на основании фактической статистики случаев, в которых заключение основного цикла проверки потребовало пересмотра.

## Модель данных и конфигурация агента

- [`models.py`](models.py) — структуры данных: результат проверки, заключение по материалу, отчёт о проверке
- [`agent.py`](agent.py) — конфигурация агента и контракт методов (без реализации логики)

## Взаимодействие с другими подсистемами

1. Агент-креатор передаёт объект `DraftBundle`
2. Агент-визуализатор передаёт объект `AssetBundle`
3. Ядро персонажа передаёт объект `CampaignContext` со ссылкой на эталонные параметры идентичности
4. При выявлении несоответствий агент формирует объекты `RevisionNote` и направляет их агенту-креатору или агенту-визуализатору
5. Материалы с заключением `approved` передаются в контур Human-in-the-Loop
6. Материалы, исчерпавшие число циклов доработки, передаются в контур Human-in-the-Loop с заключением `escalated`

## Обработка ошибок

- При недоступности эталонных параметров идентичности проверка категории `visual_consistency` не выполняется, материал передаётся в контур Human-in-the-Loop с заключением `escalated`; автоматическое одобрение без проверки консистентности не допускается
- При недоступности правил бренда клиента проверка категории `brand_compliance` не выполняется, материал передаётся в контур Human-in-the-Loop с заключением `escalated`
- При исчерпании числа циклов доработки, учёт которых ведёт API-оркестратор, материал передаётся в контур Human-in-the-Loop с заключением `escalated`
- Отсутствие заключения не может служить основанием для публикации: материал, не получивший заключения `approved`, в контур публикации не передаётся
