# Агент-аналитик метрик (Metrics Analyst)

## Роль в системе

Замыкает производственный цикл. Обрабатывает показатели эффективности опубликованных материалов и передаёт результаты анализа в ядро персонажа, систему A/B-тестирования и рабочее место команды.

## Зона ответственности

- Сведение показателей эффективности публикаций по концептам контент-плана
- Формирование выводов по результатам кампании для отчёта об эффективности
- Формирование предложения по обновлению поведенческого состояния персонажа для ядра персонажа
- Передача сводных результатов по вариантам экспериментов в систему A/B-тестирования

## Обоснование выбора модели

Подсистема выполняет обработку показателей эффективности публикаций с последующей формулировкой выводов. Применяется модель Claude Haiku 4.5, обеспечивающая требуемое качество при меньших издержках на обработку единицы данных.

## Защита данных

Методы интерпретации показателей эффективности и правила формирования выводов относятся к коммерческой тайне. Системный промпт агента размещён в закрытой ветке разработки.

## Входной контракт

Модуль принимает контекст кампании, контент-план и показатели эффективности публикаций, введённые специалистом:

```json
{
  "context": {
    "profile": { "character_id": "nick_v1", "client_id": "erzetix_media" },
    "brief": { "campaign_id": "camp_2026_demo" }
  },
  "content_plan": {
    "concepts": [
      {
        "concept_id": "cpt_001",
        "format": "short_video",
        "target_platform": "telegram",
        "ab_variant": { "experiment_id": "exp_001", "variant_id": "a" }
      }
    ]
  },
  "metrics": [
    {
      "material_id": "mat_001",
      "campaign_id": "camp_2026_demo",
      "concept_id": "cpt_001",
      "platform": "telegram",
      "published_at": "2026-09-03T10:00:00Z",
      "views": 1000,
      "reach": 800,
      "reactions": 100,
      "comments": 10,
      "shares": 5,
      "conversions": 2,
      "additional_metrics": {},
      "reported_by": "specialist_01"
    }
  ]
}
```

Структуры `CampaignContext` и `ContentPlan` соответствуют выходным контрактам ядра персонажа и агента-стратега. Числовые значения показателей в примерах приведены для иллюстрации структуры.

## Показатели эффективности

| Поле | Показатель |
|---|---|
| `views` | Просмотры |
| `reach` | Охват |
| `reactions`, `comments`, `shares` | Вовлечённость: реакции, комментарии, репосты |
| `conversions` | Конверсии |
| `additional_metrics` | Иные показатели, согласованные с компанией |

Охват и конверсии указываются при наличии данных платформы.

## Выходной контракт

Модуль возвращает результат анализа:

```json
{
  "analysis_id": "anl_001",
  "campaign_id": "camp_2026_demo",
  "character_id": "nick_v1",
  "analyzed_at": "2026-09-10T12:00:00Z",
  "concept_results": [
    {
      "concept_id": "cpt_001",
      "format": "short_video",
      "platform": "telegram",
      "material_ids": ["mat_001"],
      "views": 1000,
      "reactions": 100,
      "comments": 10,
      "shares": 5,
      "ab_variant": { "experiment_id": "exp_001", "variant_id": "a" }
    }
  ],
  "findings": [
    {
      "finding_id": "fnd_001",
      "statement": "Формулировка вывода по результатам кампании",
      "supporting_concept_ids": ["cpt_001"]
    }
  ],
  "proposed_behavioral_state": {
    "tone": "ироничный, дружелюбный",
    "recent_topics": ["..."],
    "engagement_trend": "growing"
  },
  "excluded_material_ids": []
}
```

Поле `concept_results` содержит суммарные показатели публикаций по каждому концепту. Поле `findings` используется при формировании отчёта об эффективности. Поле `proposed_behavioral_state` содержит предложение по обновлению поведенческого состояния персонажа; обновление профиля выполняет ядро персонажа.

## Модель данных и конфигурация агента

- [`models.py`](models.py) — структуры данных: показатели публикации, сводные результаты по концепту, вывод, результат анализа
- [`agent.py`](agent.py) — конфигурация агента и контракт методов (без реализации логики)

## Взаимодействие с другими подсистемами

1. Специалист вводит показатели эффективности публикаций в рабочем месте команды
2. Оркестратор передаёт агенту контекст кампании, контент-план и показатели
3. Результат анализа передаётся в ядро персонажа для обновления поведенческого состояния
4. Сводные результаты по вариантам экспериментов передаются в систему A/B-тестирования
5. Выводы используются рабочим местом команды при формировании отчёта для компании

## Обработка ошибок

- Показатели материала, концепт которого отсутствует в контент-плане, исключаются из анализа и фиксируются в поле `excluded_material_ids`
- При отсутствии показателей по кампании результат анализа возвращается с пустыми списками `concept_results` и `findings`, поле `proposed_behavioral_state` не заполняется; обновление поведенческого состояния персонажа не выполняется
