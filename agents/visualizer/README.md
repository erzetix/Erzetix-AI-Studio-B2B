# Агент-визуализатор (Visualizer)

## Роль в системе

Формирует визуальную составляющую контента. Преобразует текстовые описания визуального ряда в технические промпты генеративных сервисов, выбирает провайдера под задачу и обеспечивает визуальную консистентность персонажа между материалами.

## Зона ответственности

- Формирование технических промптов для генеративных сервисов изображений и видео
- Выбор генеративного сервиса в зависимости от формата задачи и требований к качеству
- Обеспечение визуальной консистентности персонажа (character lock) между сценами и материалами
- Формирование заданий на синтез речи по репликам персонажа
- Направление запросов во внешние сервисы через API-оркестратор
- Доработка материалов по замечаниям агента-хранителя бренда

## Обоснование выбора модели

Подсистема решает задачу преобразования описательного текста в структурированные технические промпты с учётом ограничений конкретного генеративного сервиса. Применяется модель Claude Sonnet 5, обеспечивающая требуемое качество при приемлемых издержках.

## Защита данных

Параметры визуальной идентичности персонажа (Facial DNA, Body DNA, Style DNA, Prompt DNA), шаблоны технических промптов и правила обеспечения консистентности относятся к коммерческой тайне. Модуль обращается к ним по ссылке (`identity_ref`) без раскрытия содержимого. Системный промпт агента размещён в закрытой ветке разработки.

## Матрица выбора провайдера

| Задача | Основной провайдер | Резервный провайдер |
|---|---|---|
| Изображение с максимальными требованиями к стабильности внешности | Higgsfield Soul 2.0 | Nano Banana Pro |
| Массовая генерация изображений, черновые варианты | Nano Banana 2 | Seedream 5.0 |
| Сложная композиция, рендеринг текста и элементов бренда | Nano Banana Pro | Seedream 5.0 |
| Видео | Kling 3.0 | Seedance 2.0 |
| Видео с требованием кинематографического качества и синхронизированного звука | Veo 3.1 | Kling 3.0 |
| Синтез речи | ElevenLabs | Яндекс SpeechKit |

Выбор провайдера выполняется на уровне подсистемы. Переключение на резервного провайдера при недоступности основного производится API-оркестратором без изменения логики подсистемы.

## Входной контракт

Модуль принимает набор материалов от агента-креатора и контекст кампании от ядра персонажа:

```json
{
  "context": {
    "profile": {
      "character_id": "nick_v1",
      "identity_ref": "vault://character-dna/nick_v1",
      "voice_profile_ref": "vault://voice-profile/nick_v1"
    },
    "brief": { "...": "бриф кампании" }
  },
  "draft_bundle": {
    "campaign_id": "camp_2026_demo",
    "revision": 1,
    "drafts": [
      {
        "draft_id": "drf_001",
        "format": "short_video",
        "scenes": [
          {
            "scene_index": 1,
            "duration_sec": 3,
            "spoken_line": "Реплика персонажа, предназначенная для синтеза речи",
            "visual_description": "Текстовое описание визуального ряда сцены"
          }
        ]
      }
    ]
  },
  "revision_notes": []
}
```

Структуры `CampaignContext` и `DraftBundle` соответствуют выходным контрактам ядра персонажа и агента-креатора. Преобразование данных на стыке модулей не требуется.

## Выходной контракт

Модуль возвращает набор медиаматериалов с указанием параметров генерации:

```json
{
  "campaign_id": "camp_2026_demo",
  "character_id": "nick_v1",
  "created_at": "2026-09-01T19:30:00Z",
  "revision": 1,
  "assets": [
    {
      "asset_id": "ast_001",
      "draft_id": "drf_001",
      "scene_index": 1,
      "asset_type": "video",
      "provider": "kling_3",
      "prompt_ref": "confidential://generated-prompts/ast_001",
      "storage_ref": "storage://media/camp_2026_demo/ast_001.mp4",
      "consistency_score": 0.94,
      "generation_attempts": 1
    },
    {
      "asset_id": "ast_002",
      "draft_id": "drf_001",
      "scene_index": 1,
      "asset_type": "speech",
      "provider": "elevenlabs",
      "storage_ref": "storage://media/camp_2026_demo/ast_002.mp3",
      "duration_sec": 2.8
    }
  ],
  "failed_assets": []
}
```

Поле `consistency_score` содержит оценку соответствия сгенерированного изображения эталонным параметрам внешности персонажа. Оценка выполняется подсистемой в порядке самопроверки перед выдачей результата: материалы с оценкой ниже порогового значения `min_consistency_score` направляются на повторную генерацию и агенту-хранителю бренда не передаются.

Независимая проверка визуальной консистентности выполняется агентом-хранителем бренда по категории `visual_consistency` и не заменяется самопроверкой подсистемы.

Поле `prompt_ref` содержит ссылку на сформированный технический промпт. Промпты сохраняются в защищённом хранилище и не передаются в составе выходных данных.

## Типы материалов

| Код | Значение |
|---|---|
| `image` | Статическое изображение |
| `video` | Видеоматериал |
| `speech` | Аудиоматериал синтезированной речи |

## Калибруемые параметры

Пороговое значение оценки консистентности (`min_consistency_score`) определяется по результатам калибровки на реальных данных на Этапе 2. Шкала оценки устанавливается совместно с выбором метода сравнения сгенерированного материала с эталонными параметрами внешности персонажа.

Предельное число попыток генерации (`max_generation_attempts`) подлежит уточнению по фактической статистике генерации на Этапе 2.

## Модель данных и конфигурация агента

- [`models.py`](models.py) — структуры данных: задание на генерацию, медиаматериал, набор материалов, отказ генерации
- [`agent.py`](agent.py) — конфигурация агента и контракт методов (без реализации логики)

## Взаимодействие с другими подсистемами

1. Агент-креатор передаёт объект `DraftBundle`
2. Ядро персонажа передаёт объект `CampaignContext` со ссылками на параметры идентичности
3. Агент формирует задания на генерацию и направляет их в API-оркестратор
4. API-оркестратор возвращает результаты генерации от внешних сервисов
5. Агент формирует объект `AssetBundle` и передаёт его агенту-хранителю бренда
6. При выявлении несоответствий агент-хранитель бренда возвращает материалы с объектом `RevisionNote` для доработки

## Обработка ошибок

- При недоступности основного провайдера генерация выполняется резервным провайдером согласно матрице выбора; переключение производится API-оркестратором
- При недоступности основного и резервного провайдеров материал помещается в список `failed_assets` с кодом `ALL_PROVIDERS_UNAVAILABLE`; остальные материалы набора обрабатываются в штатном режиме
- При оценке консистентности ниже порогового значения выполняется повторная генерация; число попыток ограничено значением `max_generation_attempts`, при исчерпании лимита материал эскалируется контуру Human-in-the-Loop
- При недоступности параметров идентичности персонажа обработка прерывается с кодом `IDENTITY_UNAVAILABLE`; генерация без параметров идентичности не допускается
