# Агент-креатор (Creator)

## Роль в системе

Формирует текстовую составляющую контента. Преобразует концепты контент-плана в готовые тексты, сценарии и диалоги, соответствующие голосу и коммуникативному стилю персонажа.

## Зона ответственности

- Формирование сценариев видеоматериалов с разбивкой на сцены
- Формирование текстов публикаций и сопроводительных подписей
- Формирование реплик персонажа, предназначенных для последующего синтеза речи
- Формирование текстового описания визуального ряда для агента-визуализатора
- Соблюдение ограничений, заданных в брифе кампании
- Доработка материалов по замечаниям агента-хранителя бренда

## Обоснование выбора модели

Подсистема решает задачу генеративного характера с требованием устойчивого воспроизведения стиля персонажа на протяжении всего материала. Применяется модель Claude Sonnet 5, обеспечивающая требуемое качество генерации при приемлемых издержках.

## Защита данных

Голосовые характеристики персонажа, речевые шаблоны и системный промпт агента относятся к коммерческой тайне. Модуль обращается к ним по ссылке (`voice_profile_ref`) без раскрытия содержимого. Системный промпт агента размещён в закрытой ветке разработки.

## Входной контракт

Модуль принимает контент-план от агента-стратега и контекст кампании от ядра персонажа:

```json
{
  "context": {
    "profile": {
      "character_id": "nick_v1",
      "voice_profile_ref": "vault://voice-profile/nick_v1",
      "behavioral_state": {
        "tone": "ироничный, дружелюбный"
      }
    },
    "brief": {
      "campaign_id": "camp_2026_demo",
      "constraints": ["без упоминания конкурентов", "без резких высказываний"]
    }
  },
  "content_plan": {
    "concepts": [
      {
        "concept_id": "cpt_001",
        "title": "Короткий вертикальный обзор новинки",
        "format": "short_video",
        "priority": 1,
        "key_message": "Демонстрация продукта в характерной для персонажа подаче"
      }
    ]
  },
  "revision_notes": []
}
```

Структуры `CampaignContext` и `ContentPlan` соответствуют выходным контрактам ядра персонажа и агента-стратега. Преобразование данных на стыке модулей не требуется.

Поле `revision_notes` заполняется при повторном обращении к модулю после проверки агентом-хранителя бренда.

## Выходной контракт

Модуль возвращает набор текстовых материалов по каждому концепту:

```json
{
  "campaign_id": "camp_2026_demo",
  "character_id": "nick_v1",
  "created_at": "2026-09-01T19:00:00Z",
  "revision": 1,
  "drafts": [
    {
      "draft_id": "drf_001",
      "concept_id": "cpt_001",
      "format": "short_video",
      "scenes": [
        {
          "scene_index": 1,
          "duration_sec": 3,
          "spoken_line": "Реплика персонажа, предназначенная для синтеза речи",
          "visual_description": "Текстовое описание визуального ряда сцены",
          "on_screen_text": "Текст, размещаемый в кадре"
        }
      ],
      "caption": "Сопроводительная подпись к публикации",
      "hashtags": ["#пример"]
    }
  ]
}
```

Поле `visual_description` передаётся агенту-визуализатору в качестве основы для формирования технических промптов генеративных сервисов.

## Правила формирования материалов

- Реплики персонажа формируются с учётом ограничений синтеза речи: без труднопроизносимых сочетаний, с указанием длительности сцены
- Текст, размещаемый в кадре, ограничивается по длине исходя из формата и целевой платформы
- Материалы, нарушающие ограничения брифа, не формируются; при невозможности раскрыть концепт без нарушения ограничений концепт возвращается со статусом `blocked`
- Число сцен определяется форматом и длительностью материала; фиксированное предельное значение не устанавливается

## Модель данных и конфигурация агента

- [`models.py`](models.py) — структуры данных: сцена, черновик материала, набор материалов, замечание к доработке
- [`agent.py`](agent.py) — конфигурация агента и контракт методов (без реализации логики)

## Взаимодействие с другими подсистемами

1. Агент-стратег передаёт объект `ContentPlan`
2. Ядро персонажа передаёт объект `CampaignContext` со ссылкой на голосовой профиль
3. Агент формирует объект `DraftBundle` и передаёт его агенту-визуализатору
4. При выявлении несоответствий агент-хранитель бренда возвращает материалы с объектом `RevisionNote` для доработки

## Обработка ошибок

- При недоступности голосового профиля персонажа обработка прерывается с кодом `VOICE_PROFILE_UNAVAILABLE`; формирование материалов без профиля не допускается
- При невозможности раскрыть концепт без нарушения ограничений брифа концепт возвращается со статусом `blocked` и указанием ограничения, вызвавшего конфликт; остальные концепты плана обрабатываются в штатном режиме
- Число циклов доработки ограничивается API-оркестратором; подсистема собственного счётчика циклов не ведёт. При исчерпании лимита оркестратор передаёт материал в контур Human-in-the-Loop
