# Система A/B-тестирования

## Роль в системе

Организует параллельный показ вариантов контента и сопоставляет результаты по показателям эффективности, согласованным с компанией. Формирует рекомендации по корректировке сценариев контента для агента-стратега.

## Зона ответственности

- Формирование и ведение экспериментов: гипотеза, варианты контента, целевой показатель эффективности
- Передача агенту-стратегу действующих экспериментов для включения вариантов в контент-план
- Сопоставление вариантов по результатам анализа метрик
- Формирование рекомендаций для агента-стратега по результатам, признанным достоверными

## Порядок проведения эксперимента

1. Система формирует эксперимент: гипотеза, формат контента, целевой показатель, не менее двух вариантов
2. Агент-стратег включает в контент-план концепты для каждого варианта; принадлежность концепта к варианту фиксируется в поле `ab_variant`
3. Материалы проходят производственный конвейер и публикуются в штатном порядке
4. Агент-аналитик метрик формирует сводные результаты по концептам с указанием варианта
5. Система сопоставляет варианты по целевому показателю и формирует результат эксперимента
6. По достоверному результату формируется объект `ABRecommendation`, передаваемый агенту-стратегу

## Входной контракт

Эксперимент:

```json
{
  "experiment_id": "exp_001",
  "character_id": "nick_v1",
  "hypothesis": "Формулировка проверяемой гипотезы",
  "applies_to_format": "short_video",
  "target_metric": "shares",
  "variants": [
    { "variant_id": "a", "description": "Описание варианта A" },
    { "variant_id": "b", "description": "Описание варианта B" }
  ],
  "status": "planned",
  "created_at": "2026-09-01T12:00:00Z"
}
```

Источник гипотез и порядок формирования экспериментов определяются на Этапе 2.

Для сопоставления вариантов система принимает перечень объектов `MetricsAnalysis`, сформированных агентом-аналитиком метрик. Преобразование данных на стыке не требуется.

## Выходной контракт

Результат эксперимента:

```json
{
  "experiment_id": "exp_001",
  "evaluated_at": "2026-09-15T12:00:00Z",
  "variant_results": [
    { "variant_id": "a", "concept_ids": ["cpt_001"], "publications": 1, "metric_total": 5 },
    { "variant_id": "b", "concept_ids": ["cpt_002"], "publications": 1, "metric_total": 3 }
  ],
  "conclusive": false,
  "winning_variant_id": null,
  "confidence": null
}
```

Рекомендация для агента-стратега формируется в виде объекта `ABRecommendation`, определённого в модуле агента-стратега, только по результатам со значением `conclusive` = `true`. Числовые значения в примерах приведены для иллюстрации структуры.

## Состояния эксперимента

| Код | Значение |
|---|---|
| `planned` | Эксперимент сформирован, варианты в контент-план не включены |
| `running` | Варианты включены в контент-план, выполняется сбор результатов |
| `completed` | Результат эксперимента сформирован |
| `cancelled` | Эксперимент прекращён без формирования результата |

## Калибруемые параметры

Минимальное число публикаций каждого варианта (`min_publications_per_variant`) и пороговое значение достоверности результата (`min_confidence`) определяются по результатам калибровки на реальных данных на Этапе 2 совместно с выбором метода сопоставления вариантов.

## Модель данных и операции

- [`models.py`](models.py) — структуры данных: эксперимент, вариант, результаты варианта, результат эксперимента
- [`experiments.py`](experiments.py) — конфигурация и контракт операций (без реализации логики)

## Взаимодействие с подсистемами

1. Система формирует эксперименты для персонажа
2. Агент-стратег получает действующие эксперименты персонажа при формировании контент-плана
3. Агент-аналитик метрик передаёт результаты анализа
4. Рекомендации передаются агенту-стратегу при формировании последующих контент-планов

## Обработка ошибок

- При недостаточном числе публикаций какого-либо варианта результат формируется со значением `conclusive` = `false`, рекомендация не формируется
- Эксперимент, варианты которого не включены ни в один контент-план, не переводится в состояние `running`

## Статус

Контракт и модель данных зафиксированы. Реализация сопоставления вариантов и оценки достоверности — Этап 2.
