# Рабочее место команды

## Роль в системе

Внутренний интерфейс команды, ведущей аккаунты компаний. Обеспечивает постановку задач, утверждение контента, ввод показателей эффективности публикаций и доступ к отчётам об эффективности.

Компании в работе комплекса непосредственно не участвуют и доступа к рабочему месту команды не имеют. Решения о содержании и публикации материалов принимает команда. Взаимодействие с компанией — обсуждение персонажа, согласование отдельных материалов, корректировка направления ведения аккаунта — выполняется вне комплекса.

Контур Human-in-the-Loop реализован средствами рабочего места команды.

## Зона ответственности

- Ведение перечня компаний и параметров ведения их аккаунтов
- Формирование брифа кампании и передача его оркестратору
- Отображение статуса кампаний и материалов в производственном конвейере
- Утверждение материалов и возврат их на доработку в контуре Human-in-the-Loop
- Ввод показателей эффективности публикаций
- Предоставление автоматически сформированных отчётов об эффективности

## Утверждение материалов

Каждый материал перед публикацией утверждается специалистом по производству контента. Передача материала в публикацию без утверждения человеком не предусмотрена.

До утверждения материал проходит автоматические циклы доработки по замечаниям агента-хранителя бренда. На утверждение передаются материалы, получившие заключение `approved`, а также материалы с заключением `escalated`.

Утверждение и возврат на доработку выполняются для каждого материала отдельно. Возврат материала не затрагивает остальные материалы кампании.

При возврате материала на доработку специалист указывает замечания (`RevisionNote`) и адресата: агента-креатора при замечаниях к тексту, агента-визуализатора при замечаниях к визуальному ряду. Доработанный материал повторно проходит проверку агентом-хранителем бренда и возвращается на утверждение.

## Отчёты об эффективности

Отчёт об эффективности формируется автоматически по показателям эффективности публикаций и результатам анализа агента-аналитика метрик за период: перечень кампаний, число опубликованных материалов, показатели публикаций, выводы по результатам анализа.

## Специалисты команды

Операции рабочего места выполняются специалистами по производству контента. Распределение зон ответственности между специалистами определяется отдельным организационным документом.

## Точки входа

Перечень точек входа приведён в [`api.py`](api.py).

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/clients` | Добавление компании |
| `GET` | `/clients` | Получение списка компаний |
| `GET` | `/clients/{client_id}` | Получение параметров компании |
| `GET` | `/clients/{client_id}/characters` | Получение персонажей компании |
| `GET` | `/characters/{character_id}` | Получение профиля персонажа |
| `POST` | `/campaigns` | Создание кампании на основании брифа |
| `GET` | `/campaigns` | Получение списка кампаний |
| `GET` | `/campaigns/{campaign_id}` | Получение состояния кампании |
| `GET` | `/campaigns/{campaign_id}/materials` | Получение материалов кампании |
| `POST` | `/materials/{material_id}/approve` | Утверждение материала |
| `POST` | `/materials/{material_id}/return` | Возврат материала на доработку с замечаниями |
| `GET` | `/campaigns/{campaign_id}/metrics` | Получение показателей эффективности |
| `POST` | `/campaigns/{campaign_id}/metrics` | Ввод показателей эффективности публикаций |
| `GET` | `/clients/{client_id}/report` | Получение отчёта об эффективности за период |

## Выходной контракт

Представление материала в контуре утверждения:

```json
{
  "material_id": "mat_001",
  "campaign_id": "camp_2026_demo",
  "concept_id": "cpt_001",
  "draft_id": "drf_001",
  "format": "short_video",
  "state": "awaiting_approval",
  "preview_ref": "storage://media/camp_2026_demo/mat_001.mp4",
  "caption": "Сопроводительная подпись к публикации",
  "guardian_verdict": "approved",
  "failed_checks": [],
  "created_at": "2026-09-01T19:30:00Z"
}
```

Возврат материала на доработку:

```json
{
  "material_id": "mat_002",
  "approved": false,
  "decided_by": "specialist_01",
  "decided_at": "2026-09-02T12:30:00Z",
  "revision_notes": [
    {
      "note_id": "nte_101",
      "draft_id": "drf_002",
      "target_agent": "creator",
      "author": "specialist",
      "issue": "Подпись не соответствует тону коммуникации персонажа",
      "required_action": "Переформулировать подпись"
    }
  ]
}
```

Поле `preview_ref` содержит ссылку на готовый медиафайл в хранилище. Выдача содержимого выполняется с проверкой прав доступа сотрудника.

## Модель данных и точки входа

- [`models.py`](models.py) — структуры данных: компания, представление материала, представление кампании, решение об утверждении, отчёт об эффективности
- [`api.py`](api.py) — перечень точек входа и контракт операций (без реализации логики)

## Взаимодействие с подсистемами

1. Специалист формирует бриф и передаёт его оркестратору, получает идентификатор кампании
2. Состояние кампании и материалов запрашивается у оркестратора
3. Материалы с заключением агента-хранителя бренда отображаются в контуре утверждения
4. Решение по материалу передаётся оркестратору и определяет дальнейший переход состояния этого материала
5. Показатели эффективности (`PublicationMetrics`), введённые специалистом, передаются агенту-аналитику метрик
6. Отчёт об эффективности формируется по показателям эффективности и результатам анализа метрик за период

## Обработка ошибок

- При недоступности оркестратора отображается последнее известное состояние кампании с указанием времени получения данных; операции утверждения в этом случае недоступны
- Утверждение или возврат материала, не находящегося в состоянии `awaiting_approval`, отклоняется с кодом `INVALID_MATERIAL_STATE`
- Возврат материала на доработку без замечаний отклоняется с кодом `REVISION_NOTES_REQUIRED`
