# Рабочее место команды

## Роль в системе

Внутренний интерфейс команды, ведущей аккаунты компаний. Обеспечивает постановку задач, утверждение контента, ввод показателей эффективности публикаций и формирование отчётов для компаний.

Компании в работе комплекса непосредственно не участвуют и доступа к рабочему месту команды не имеют. Решения о содержании и публикации материалов принимает команда. Согласование отдельных материалов с компанией и корректировка направления ведения аккаунта выполняются вне комплекса — на созвонах и в переписке; результаты согласования фиксируются в рабочем месте сотрудником команды.

Контур Human-in-the-Loop реализован средствами рабочего места команды.

## Зона ответственности

- Ведение перечня компаний и параметров ведения их аккаунтов
- Формирование брифа кампании на основании договорённостей с компанией и передача его оркестратору
- Отображение статуса кампаний в производственном конвейере
- Отображение сформированных материалов
- Утверждение и отклонение материалов командой в контуре Human-in-the-Loop
- Назначение согласования отдельных материалов с компанией и фиксация решения компании
- Ввод показателей эффективности публикаций
- Формирование периодических отчётов для компаний

## Режимы утверждения

| Код | Порядок утверждения |
|---|---|
| `manual` | Каждый материал утверждается командой |
| `hybrid` | Утверждение командой требуется для материалов, получивших заключение `escalated` либо не прошедших отдельные категории проверок |
| `autonomous` | Утверждение командой не требуется, материалы с заключением `approved` передаются в модуль публикации |

Режим устанавливается отдельно для каждой компании.

## Согласование с компанией

Для отдельных материалов сотрудник команды назначает согласование с компанией. Такой материал после утверждения командой переходит в состояние `awaiting_client_signoff` и передаётся в публикацию только после фиксации решения компании.

Решение компании фиксируется сотрудником команды в виде объекта `ApprovalDecision` со значением `source` = `client` и указанием канала, по которому решение получено. Отклонение материала компанией возвращает кампанию на доработку в том же порядке, что и отклонение командой.

Назначение согласования выполняется независимо от режима утверждения: материал, для которого назначено согласование с компанией, не передаётся в публикацию без решения компании в том числе в автономном режиме.

## Отчётность для компании

Компания получает периодический отчёт о ведении аккаунта: перечень кампаний за период, число опубликованных материалов и показатели эффективности публикаций. Отчёт формируется сотрудником команды и направляется компании вне комплекса.

Периодичность отчёта устанавливается договором с компанией и задаётся в параметрах компании (`report_period_days`).

| Роль | Доступные операции |
|---|---|
| `account_manager` | Ведение компаний, формирование брифов, утверждение материалов, согласование с компанией, формирование отчётов |
| `content_specialist` | Утверждение материалов, ввод показателей эффективности публикаций |

## Точки входа

Перечень точек входа приведён в [`api.py`](api.py).

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/clients` | Получение списка компаний |
| `GET` | `/clients/{client_id}` | Получение параметров компании |
| `POST` | `/campaigns` | Создание кампании на основании брифа |
| `GET` | `/campaigns` | Получение списка кампаний |
| `GET` | `/campaigns/{campaign_id}` | Получение состояния кампании |
| `GET` | `/campaigns/{campaign_id}/materials` | Получение материалов кампании |
| `POST` | `/materials/{material_id}/approve` | Утверждение материала командой |
| `POST` | `/materials/{material_id}/reject` | Отклонение материала с указанием причины |
| `POST` | `/materials/{material_id}/client-signoff` | Назначение согласования с компанией |
| `POST` | `/materials/{material_id}/client-decision` | Фиксация решения компании |
| `GET` | `/campaigns/{campaign_id}/metrics` | Получение показателей эффективности |
| `POST` | `/campaigns/{campaign_id}/metrics` | Ввод показателей эффективности публикаций |
| `POST` | `/clients/{client_id}/reports` | Формирование отчёта для компании |
| `GET` | `/characters/{character_id}` | Получение профиля персонажа |

## Выходной контракт

Представление материала в контуре утверждения:

```json
{
  "material_id": "mat_001",
  "campaign_id": "camp_2026_demo",
  "draft_id": "drf_001",
  "format": "short_video",
  "state": "awaiting_approval",
  "preview_ref": "storage://media/camp_2026_demo/ast_001.mp4",
  "caption": "Сопроводительная подпись к публикации",
  "guardian_verdict": "approved",
  "failed_checks": [],
  "client_signoff_required": true,
  "created_at": "2026-09-01T19:30:00Z"
}
```

Решение компании, зафиксированное сотрудником команды:

```json
{
  "material_id": "mat_001",
  "approved": true,
  "source": "client",
  "decided_by": "account_manager_01",
  "decided_at": "2026-09-02T12:00:00Z",
  "client_channel": "созвон"
}
```

Поле `preview_ref` содержит ссылку на материал в хранилище. Выдача содержимого выполняется с проверкой прав доступа сотрудника.

## Модель данных и точки входа

- [`models.py`](models.py) — структуры данных: компания, представление материала, представление кампании, решение об утверждении, показатели эффективности, отчёт для компании
- [`api.py`](api.py) — перечень точек входа и контракт операций (без реализации логики)

## Взаимодействие с подсистемами

1. Сотрудник команды формирует бриф и передаёт его оркестратору, получает идентификатор кампании
2. Состояние кампании запрашивается у оркестратора
3. Материалы с заключением агента-хранителя бренда отображаются в контуре утверждения
4. Решение об утверждении передаётся оркестратору после получения всех требуемых согласований и определяет дальнейший переход состояния кампании
5. Показатели эффективности, введённые специалистами по производству контента, передаются агенту-аналитику метрик
6. Отчёт для компании формируется по показателям эффективности публикаций за период

## Обработка ошибок

- При недоступности оркестратора отображается последнее известное состояние кампании с указанием времени получения данных; операции утверждения в этом случае недоступны
- Утверждение материала, не находящегося в состоянии `awaiting_approval`, отклоняется с кодом `INVALID_MATERIAL_STATE`
- Фиксация решения компании по материалу, не находящемуся в состоянии `awaiting_client_signoff`, отклоняется с кодом `INVALID_MATERIAL_STATE`
- Операции, недоступные роли сотрудника, отклоняются с кодом `FORBIDDEN` без раскрытия сведений о существовании запрошенного объекта
